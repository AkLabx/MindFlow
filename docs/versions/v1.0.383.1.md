## 2. Executive Summary
Executed a focused backend and Single Source of Truth (SSOT) standardization point release (**`v1.0.383.1`**) without disturbing the pre-planned `v1.0.384` roadmap. Audited and normalized all `11,034` rows in `public.questions` (`10,991` active across `21` canonical `examName` codes and `203` consolidated `examDateShift` strings; `43` soft-deleted), enforced the **Official Notification Year** Golden Rule for `examYear`, established `public.exam_catalog` (25 exams) and `public.exam_cycles` (50 cycles) as the database SSOT with `CHECK` + FK constraints and soft-delete-aware RPCs, and synchronized AI extraction (`extract-questions.ts`), offline-first IndexedDB catalog caching (`examCatalogService.ts`), and Admin authoring controls.

## 4. Engineering Decisions (Path A vs Path B)
### Decision 1: DB-Backed `exam_catalog` + `exam_cycles` SSOT vs Client-Only Aliasing (`DEC-0001` Amended, `OLD-022`)
- **Context & Problem Statement**: `public.questions` accumulated 20+ fragmented `examName` variants (`BPSC CSE PRE` mixing non-CCE exams, split `SSC CGL` strings), held-year vs notification-year conflations in `examYear`, and 330+ inconsistent `examDateShift` strings (`N/A`, book-scraped variants).
- **Path A (Alternative Considered)**: Keep adding client-side regex aliases and display maps while leaving `questions` columns unconstrained free-text.
- **Path B (Path Chosen)**: Normalize all historical rows atomically under the **Official Notification Year** Golden Rule, enforce canonical values at write time via `public.exam_catalog` FK (`ON UPDATE CASCADE`) + `CHECK` constraints, and propagate the catalog to `extract-questions.ts`, `examCatalogService.ts` offline fallback, and Admin selects.
- **Do-Not-Break Invariant**: Never insert uncataloged `examName` strings or mix exam-held calendar year with official notification year in `examYear`.
- **Decision ID Registered in Ledger**: `DEC-0001` *(Amended `v1.0.383.1`)* & `OLD-022`.

## 5. Runtime Bugs & Platform Quirks Handled During Execution
| Bug / Edge Case Caught | Root Cause | Failure Manifestation | Surgical Remedy Applied |
| :--- | :--- | :--- | :--- |
| Bulk backfill trigger overhead & cache drift risk | Updating 11k rows row-by-row with `trg_questions_refresh_subject_metadata_cache` active slows migrations and risks transient cache skew | Heavy per-row recalculation across `questions` | Temporarily disabled trigger during atomic SQL backfill, re-enabled, and refreshed `subject_metadata_cache` across all 13 subjects (`cache_drift_rows = 0`) |
| Supabase MCP auto-cancelling `DROP` DDL | MCP confirmation guard cancels `apply_migration` calls containing `DROP INDEX` / `DROP CONSTRAINT` | `drop_duplicate_question_indexes` cancelled automatically | Separated additive DDL/constraints into `create_exam_catalog_ssot_tables` + `enforce_exam_source_constraints_and_rpcs`, and preserved 6 duplicate lowercase `DROP INDEX` statements as comments for manual SQL Editor execution |
| `get_contextual_filter_counts` returning soft-deleted shifts/exams | Existing overloaded RPC functions lacked `deleted_at IS NULL` filters | Soft-deleted rows (`'Demo'`, duplicate `BPSC DSO`) could appear in filter counts | Updated both `get_contextual_filter_counts` overloads to enforce `deleted_at IS NULL` (`rpc_examname_sum = 10991` verified against active rows) |
