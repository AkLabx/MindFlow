## 4. Engineering Decisions (Path A vs Path B)
### Decision 1: Dual-View Scorecard & Focused 1-by-1 Solution Review Switcher
- **Context & Problem Statement**: Prepared BPSC mock tests contain 103–150 questions. Displaying all 150 questions in a continuous single-page vertical scroll below the scorecard causes heavy DOM node inflation, sluggish scroll performance on mobile WebViews, and makes reviewing specific mistakes cumbersome.
- **Path A (Alternative Considered)**: Continuous vertical feed of 150 questions directly under the scorecard summary.
  - *Why Rejected*: Inflates DOM with 150 question cards and explanations, causing visual lag on mobile Android WebView and forcing extensive scrolling.
- **Path B (Path Chosen)**: Dual-View Switcher on `PreparedMockResultPage`. View A renders the high-level Scorecard & Subject Breakdown with a prominent "Review Solutions" CTA; View B switches to a focused 1-by-1 Question Review carousel with Previous/Next controls, quick-jump grid drawer (`<NativeDialog variant="drawer-right">`), and filter chips (`All`, `Correct`, `Incorrect`, `Unanswered`).
  - *Why Chosen / Evidence*: Keeps DOM lightweight (<16ms frame budget), lets students focus deeply on one question's explanation at a time, and provides instant 1-tap jump to any question (e.g. Q85).
- **Do-Not-Break Invariant**: Always provide 1-by-1 carousel navigation with quick-jump palette for 100+ question mock solution reviews (`DEC-0022`).
- **Decision ID Registered in Ledger**: `DEC-0022`

## 5. Runtime Bugs Caught & Fixes During Development
| Bug / Edge Case Caught | Root Cause | Failure Manifestation | Surgical Remedy Applied |
| :--- | :--- | :--- | :--- |
| Infinite hydration loop on `PreparedMockResultPage` | `loadResultData` had state objects (`attempt`, `test`, `questions.length`) in its `useCallback` dependency array | Updating state inside `loadResultData` re-created the callback and triggered `useEffect`, causing infinite reload spinner | Scoped dependencies strictly to `[attemptId, testId, userId]` with local sync snapshot caching |
| `expect is not defined` in test file | Importing `@testing-library/jest-dom` without global expect extension | Vitest runner failed to start with `ReferenceError: expect is not defined` | Removed redundant jest-dom import and used native Vitest matchers (`toBeTruthy`, `toBe`, `toContain`) matching codebase conventions |
| Out-of-memory during full-repo `tsc` | Default Node 2GB heap limit on Windows running TypeScript across 5,484 modules | `Fatal process out of memory: Zone` crashed bare `npx.cmd tsc` | Executed `node --max-old-space-size=4096 ./node_modules/typescript/bin/tsc --noEmit` which completed with 0 errors |
| Missing mock result route in `preparedMockExamRunner.test.tsx` | Route mock only declared `/mcqs/test-series/test/:testId` | Submitting navigated to result route, which was not mounted in test router | Added `<Route path="/mcqs/test-series/test/:testId/result/:attemptId" />` to test mock router |
