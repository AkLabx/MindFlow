## 2. Executive Summary
Executed Gen 2 Step 1 (`v1.0.381`) alongside a strategic Gen 2 product pivot toward **Student-First UX Simplification, Centralized Assessment & Paid Mock Test Courses**. Decluttered the Student Home (`/dashboard`) into 4 focused sections, centralized all custom practice tools under Custom Quiz Studio (`/mcqs`), relocated Target Exam selection into `ProfilePage`, unified `Quiz History` (`/quiz/library`) and the tabbed Mock Test Series Hub (`/mcqs/test-series`), raised custom/mock question limits to `300` with custom/Admin Quick Pick inputs, standardized `Saved Questions` naming with native `<ConfirmDialog>`, and shipped a reusable Top-Layer `!` `<InfoHintPopover />` component across student and admin workflows.

## 4. Engineering Decisions (Path A vs Path B)
### Decision 1: Gen 2 Student-First UX Pivot, Centralized Studio & Top-Layer `!` Guidance
- **Context & Problem Statement**: Student Home (`/dashboard`) had accumulated Target Exam, Subject, and Community/AI strips alongside separate Mock/Custom resume surfaces, `100`-question custom ceilings blocked full-length 150-question practice builds, `BookmarksPage` still used `window.confirm()`, and complex Admin/Student options lacked concise inline guidance. Meanwhile, product priority shifted from Community Study Chatrooms to **Student-First UX Simplification & Paid Mock Test Courses**.
- **Path A (Alternative Considered)**:
  - Description: Continue Gen 2 with Community Chatrooms hardening while keeping multi-strip Home cards, `100`-Q cap, and third-party tooltip libraries (`floating-ui`) for contextual help.
  - Why Rejected: Left Home cluttered on mobile viewports, blocked 150–300-Q custom quizzes, added unnecessary bundle weight instead of MWG primitives, and misaligned engineering effort with student assessment and paid mock courses.
- **Path B (Path Chosen)**:
  - Description: Pivot Gen 2 (`v1.0.381` $\rightarrow$ `v1.0.390`) to Student-First UX Simplification & Paid Mock Test Courses; reduce Home to 4 sections; centralize Custom Quiz Studio at `/mcqs`; move Target Exam selection into `ProfilePage` (`STATE_OWNERSHIP_REGISTRY`); unify `Quiz History` and tabbed Mock Test Series Hub; raise caps to `300`; and build MWG native Top-Layer + CSS Anchor Positioning `<InfoHintPopover />`.
  - Why Chosen / Evidence: Eliminated Home visual noise, kept `0ms` IndexedDB/SWR hydration across unified history and mock tabs, passed all `44` Vitest suites (`282` tests) and live Chrome DevTools MCP audits with `0` sub-44px targets and `0px` horizontal overflow.
- **Do-Not-Break Invariant**: Preserve 4-section Home (`/dashboard`), `/mcqs` studio, `ProfilePage` authorized consumer status in `stateOwnershipRegistry.ts`, `300`-Q caps, Top-Layer `<InfoHintPopover />`, and do not revive Home clutter or Community Chatrooms in Gen 2 without explicit user request (`DEC-0029`, `OLD-018`).
- **Decision IDs Registered in Ledger**: `DEC-0029`, `OLD-018`

## 5. Runtime Bugs Caught & Fixes During Development
| Bug / Edge Case Caught | Root Cause | Failure Manifestation | Surgical Remedy Applied |
| :--- | :--- | :--- | :--- |
| `InfoHintPopover` positioning in jsdom & legacy WebViews | Native `popover="auto"` and CSS `anchor-name` / `position-area` are unavailable or partial in jsdom and older engines | Popover failed to open or clipped off-screen when CSS Anchor Positioning was unsupported | Added capability detection (`CSS.supports` + `showPopover`), `:popover-open` fallback override, and viewport-clamped `position: fixed` coordinate calculation in `InfoHintPopover.tsx` |
| Native `window.confirm()` reset in Saved Questions | Legacy `BookmarksPage.tsx` still invoked blocking browser `confirm()` for Reset All | Broke native Android WebView dialog UX and lacked Toast confirmation | Replaced with `<ConfirmDialog>` + `useNotification()` Popover toasts and loading lock in `BookmarksPage.tsx` |
| Profile stats omitted Prepared Mock attempts | `useProfileStats.ts` only read custom `quiz_history` from IndexedDB | Completed BPSC/SSC prepared mocks did not increment user accuracy, tests, or time spent | Extracted `computeCombinedProfileStats()` in `useProfileStats.ts` merging `quiz_history` with completed `ContinueLearningItem` entries |
| Admin Quick Pick could pick already-selected questions | Naive `range(0, N-1)` without accounting for `selectedIdSet` would yield fewer than `N` new questions | Tapping `Pick 25` added fewer than 25 new items when matches overlapped existing selections | Over-fetched `Math.min(MAX_QUICK_PICK_QUESTIONS, targetCount + selectedIdSet.size)`, filtered `!selectedIdSet.has(q.id)`, and sliced `targetCount` |
