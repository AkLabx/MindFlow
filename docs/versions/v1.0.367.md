## 4. Engineering Decisions (Path A vs Path B)

### Decision 1: Dedicated 4-Step Full-Page Mock Test Studio vs Side-Drawer Modal
- **Context & Problem Statement**: Assembling up to 150 questions alongside metadata, marking schemes, schedule windows, and publish readiness checks inside a narrow `RightDrawer` overlay cramped the `QuestionBuilder` dual-pane UI and risked accidental dismissal or mobile viewport crowding.
- **Path A (Alternative Considered)**:
  - Description: Keep all Mock Test authoring inside the `TestDrawer` slide-over modal.
  - Why Rejected: Restricted horizontal workspace for question search/selection, degraded mobile usability, and coupled form submission with nested interactive builder controls.
- **Path B (Path Chosen)**:
  - Description: Dedicated 4-step full-page studio (`AdminTestBuilderPage`) at `/admin/test-series/tests/new` and `/admin/test-series/tests/:testId/edit` with `?step=1..4` sync, while retaining `CategoryDrawer` and `SeriesDrawer` for simpler entities and keeping `TestDrawer` repaired for export integrity.
  - Why Chosen / Evidence: Provides full-width question assembly, clean MWG step-by-step focus and validation, deep-link reload hydration via `fetchTestById`, and deterministic Android hardware back return to `/admin/test-series?tab=tests`.
- **Do-Not-Break Invariant**: Never revert Mock Test creation/editing back to a side drawer or wrap `QuestionBuilder` inside a `<form>` element.
- **Decision ID Registered in Ledger**: `DEC-0014` (`OLD-006`)

### Decision 2: MindFlow Top-Layer Popover `useNotification()` vs `react-hot-toast`
- **Context & Problem Statement**: `TestDrawer` and CMS components had calls to `react-hot-toast`, which had no mounted `<Toaster />` in the app root, causing validation and preset feedback to fail silently.
- **Path A (Alternative Considered)**:
  - Description: Mount a separate `react-hot-toast` `<Toaster />` alongside MindFlow's Top-Layer Popover notification system.
  - Why Rejected: Duplicates toast infrastructure, conflicts with Top-Layer `<dialog>` stacking (`DEC-0007`), and violates "One Concept $\rightarrow$ One Control".
- **Path B (Path Chosen)**:
  - Description: Use MindFlow's canonical `useNotification()` store (`@/stores/useNotificationStore`) for all toast feedback in `AdminTestBuilderPage` and `TestDrawer`, plus inline `role="alert"` summaries and field errors.
  - Why Chosen / Evidence: Top-Layer Popover toasts render reliably above native `<dialog>` sheets and across full-page routes.
- **Do-Not-Break Invariant**: Always use `useNotification()` (never `window.alert()` or unmounted `react-hot-toast`) for CMS toast notifications.
- **Decision ID Registered in Ledger**: `DEC-0014`

## 5. Runtime Bugs Caught & Fixes During Development

| Bug / Edge Case Caught | Root Cause | Failure Manifestation | Surgical Remedy Applied |
| :--- | :--- | :--- | :--- |
| **`QuestionBuilder` buttons submitting parent `<form>`** | Internal buttons inside `QuestionBuilder` lacked `type="button"` and were nested inside `<form>` in `TestDrawer`. | Clicking `Add to test`, filter pills, or remove accidentally triggered form submit/validation errors. | Isolated `<QuestionBuilder>` completely outside any `<form>` in both `AdminTestBuilderPage` (Step 3) and `TestDrawer`. |
| **React render-phase `setState` warning during question selection** | `QuestionBuilder` called `onChange(...)` synchronously inside its `setSelectedQuestions(prev => ...)` updater. | React logged `Cannot update a component while rendering a different component` when toggling questions. | Deferred `setFormData` in `handleQuestionIdsChange` with `queueMicrotask` + `isMountedRef` guard (root fix scheduled in `v1.0.368`). |
| **Silent `react-hot-toast` notifications** | `react-hot-toast` had no mounted `<Toaster />` in the application tree. | Validation blocks and preset confirmations gave zero visible toast feedback. | Replaced `react-hot-toast` with MindFlow Top-Layer Popover `useNotification()` toasts and inline `role="alert"` banners. |
| **Falsy-zero defaults & `series.find()` count bug** | `||` treated `0` (`negative_marks`, `passing_marks`, `display_order`) as falsy; `series.find()` only counted tests in the first series per category. | `0` snapped to `0.25` / `33`; Category cards undercounted tests across multiple series; hover-only buttons disappeared on touch screens. | Switched to `??` + string-backed state, precomputed $O(C+S+T)$ `categoryStats` `Map`, and made `>=44x44px` card action bars always visible. |
