## 4. Engineering Decisions (Path A vs Path B)
### Decision 1: Unified Gesture Swipe, Modular Onboarding Registry, Bundle Mapping & `MIND-` Rebrand (`DEC-0034`)
- **Context & Problem Statement**: Discrete CSS scroll-snap lacked 1:1 finger tracking and clashed with horizontal `.mf-h-rail` shelves; leaderboards cluttered pre-test cards; onboarding lacked pattern-specific official rules, symbol legends, and mandatory declaration gates; and `MF-` prefixes, unbundled courses, single-exam hiding, and alphabetical shift sorting degraded student UX.
- **Path A (Alternative Considered)**: Pull in an external touch-carousel npm package, duplicate `TestDetailPage` variants per exam board, keep `MF-` prefixes, and leave `TestLeaderboardCard` embedded across listing/detail views.
- **Path B (Path Chosen)**: Zero-dependency `rAF` + `translate3d` `SwipeableTabViewport` with `[data-h-rail]` edge/overflow arbitration (`0.28x` edge rubber-band, `22%` / `0.45 px/ms` snap); declarative `examOnboardingRegistry` feeding Step 0/1/2 onboarding into `/exam/:testId`; additive `mock_series_bundle_items` + `resolveEffectiveSeriesEntitlement`; `<MockTestListCard />` inline `#01` + shift badges + dynamic CTAs; exclusive `Leaderboard` tab in 3-tab `PreparedMockResultPage`; `MIND-` / `ORD-` prefixes with `MF-` auto-heal; and `QuizConfig` multi-exam + `compareExamDateShiftsDesc`.
- **Do-Not-Break Invariant**: Keep `<TestLeaderboardCard />` exclusively inside `PreparedMockResultPage` `Leaderboard` tab; preserve `[data-h-rail]` / `.mf-h-rail` swipe arbitration; require language + `EXAM_INTEGRITY_DECLARATION` in onboarding; keep `examDomainGroups` visible across multi-exam picks; and preserve graceful client fallback until `20261126220000` is applied remotely.
- **Decision ID Registered in Ledger**: `DEC-0034` (`OLD-024`).
