## 4. Engineering Decisions (Path A vs Path B)
### Decision 1: Non-Destructive `ALTER POLICY` + Privacy-Safe `get_test_leaderboard` RPC & Client Schedule Defense-in-Depth
- **Context & Problem Statement**:
  1. `user_test_attempts` allowed any caller (`TO public`) to read every completed attempt row, exposing raw `answers` JSONB.
  2. Supabase MCP's elicitation confirmation auto-cancelled `DROP POLICY` DDL statements, while `PERMISSIVE` admin policies (`is_admin()`) would still bypass student schedule RLS when an admin previews student pages.
- **Path A (Alternative Considered)**:
  - Description: Leave `user_test_attempts` readable directly via column filtering in PostgREST, rely solely on RLS for schedule windows, and require interactive `DROP POLICY` confirmation.
  - Why Rejected: PostgREST `SELECT` policies are row-level (not column-level), so any `SELECT` access exposes `answers`; admin accounts browsing student pages bypass student `PERMISSIVE` policies unless the API enforces schedule windows too.
- **Path B (Path Chosen)**:
  - Description: Lock down `"Public read for leaderboard if completed"` via `ALTER POLICY ... TO authenticated USING (false)`, serve rankings through authenticated `SECURITY DEFINER` RPC `public.get_test_leaderboard` (`SET search_path = public, pg_temp`), enforce schedule-window + active-parent checks in both RLS and `mockTestsApi.ts`, and guard `createTest`/`updateTest`/`toggleTestPublish` + Postgres `CHECK` constraints.
  - Why Chosen / Evidence: Applied cleanly in one atomic migration (`{"success":true}`), confirmed 0 leaks via `pg_policies`, function privileges, and `get_advisors(type="security")`, and verified across `14/14` CMS + security unit/contract tests.
- **Do-Not-Break Invariant**: Never add a permissive cross-user `SELECT` policy to `user_test_attempts`, never expose `answers` JSONB from `get_test_leaderboard`, never grant `EXECUTE` on `get_test_leaderboard` to `anon`/`PUBLIC`, and always keep `isTestWithinScheduleWindow()` active on student test queries.
- **Decision ID Registered in Ledger**: `DEC-0017` (and `OLD-009`)
