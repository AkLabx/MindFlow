## 2. Executive Summary
Gen 2 Step 5B (`v1.0.385.2`) delivers an end-to-end **Free Email + 6-Digit OTP** authentication experience across Signup Verification, Passwordless Sign-In, and In-App Password Recovery (backed by Brevo Custom SMTP on Supabase Free Plan) with zero new npm dependencies while preserving existing confirmation and recovery email links as seamless fallbacks. Built a reusable, Google Chrome Modern Web Guidance (`sms-otp-form`, `forms`) compliant `<EmailOtpInput />`, added `Password | Email OTP` sign-in toggling with `shouldCreateUser: false` to protect mandatory DPDP Act 2023 consent on Create Account, wired `verifyOtp` for `'signup'`, `'email'`, and `'recovery'`, and added a `mindflow_recovery_otp_pending` redirect guard in `NavigationManager.tsx` so in-app recovery OTP routes deterministically to `#/reset-password` without racing against `GUEST_ONLY` redirection.

### ✨ Features Added / Modified
- **Reusable `<EmailOtpInput />` (`src/features/auth/components/EmailOtpInput.tsx`):**
  - Single semantic `<input type="text" inputMode="numeric" autoComplete="one-time-code" pattern="\d{6}" maxLength={6}>` (avoiding `type="number"` and 6-box DOM splitting so browser/OS autofill, leading zeros, and paste work reliably).

  - Integrated `<EmailOtpInput />` inside `step = 'verify-email'` calling `supabase.auth.verifyOtp({ email, token, type: 'signup' })` alongside the existing 3-layer confirmation link watcher (`BroadcastChannel`, `focus`/`visibilitychange`, 4s poll) and `"I've Verified — Continue"` fallback.
- **Passwordless Email OTP Sign-In (`src/features/auth/components/AuthPage.tsx`):**
  - Added `Password | Email OTP` segmented tab toggle (`role="tablist"`, `>=44px` controls) inside Sign-In credentials step.
  - Calls `supabase.auth.signInWithOtp({ email, options: { shouldCreateUser: false, emailRedirectTo } })`; when an unregistered email attempts OTP sign-in (`Signups not allowed for otp` / `user not found`), displays inline guidance with a 1-tap `"Create Account Instead"` CTA so DPDP 18+/Terms consent remains mandatory.
  - Verifies 6-digit sign-in codes via `supabase.auth.verifyOtp({ email, token, type: 'email' })` with brute-force lockout parity.
- **In-App Recovery OTP + `NavigationManager` Guard (`AuthPage.tsx`, `NavigationManager.tsx`, `ResetPasswordPage.tsx`):**
  - Renders an inline 6-digit recovery `<EmailOtpInput asForm={false} />` after `resetPasswordForEmail()`, verifying via `supabase.auth.verifyOtp({ email, token, type: 'recovery' })` and navigating directly to `#/reset-password` while keeping `extractAuthHashParams()` link recovery intact.
  - Added `mindflow_recovery_otp_pending` (`sessionStorage`) guard in `NavigationManager.tsx` (cleared on error or when `ResetPasswordPage.tsx` mounts) to prevent `GUEST_ONLY` auth state transitions from redirecting to `/dashboard` before `/reset-password` renders.

  - Added 4 comprehensive test cases covering `sanitizeOtpCode` / `<EmailOtpInput />` paste & 60s cooldown, signup `verifyOtp('signup')` + expired token handling, passwordless `signInWithOtp({ shouldCreateUser: false })` + DPDP redirect + `verifyOtp('email')`, and recovery `verifyOtp('recovery')` -> `/reset-password` navigation (`13/13` passing).

## 4. Engineering Decisions (Path A vs Path B)
### Decision 1: Single-Input MWG `<EmailOtpInput />`, `shouldCreateUser: false` DPDP Guard & Recovery OTP Redirect Guard (`DEC-0037`)
- **Context & Problem Statement**: Multi-box OTP inputs break native `autocomplete="one-time-code"` autofill and paste; naive `signInWithOtp({ email })` silently registers new users without DPDP Act 2023 consent; and calling `verifyOtp({ type: 'recovery' })` inside `GUEST_ONLY` `AuthPage` fires `onAuthStateChange` before `navigate('/reset-password')` runs, risking a race redirect to `/dashboard`.
- **Path A (Alternative Considered)**: Split 6 separate `maxLength="1"` inputs, allow `signInWithOtp` auto-registration, and rely solely on `navigate('/reset-password')` after `verifyOtp` resolves.
- **Path B (Path Chosen)**: Use a single MWG-compliant `<input type="text" inputMode="numeric" autoComplete="one-time-code">` with `sanitizeOtpCode()` paste normalization and `asForm={false}` support inside parent forms; enforce `shouldCreateUser: false` on `signInWithOtp` with a 1-tap `"Create Account Instead"` DPDP rescue CTA; and set `sessionStorage.mindflow_recovery_otp_pending = 'true'` before `verifyOtp({ type: 'recovery' })`, honored first in `NavigationManager.tsx` and cleared on error or `ResetPasswordPage` mount.
- **Do-Not-Break Invariant**: Always keep `<EmailOtpInput />` as a single `type="text" inputMode="numeric" autoComplete="one-time-code"` input (never `type="number"` or 6 split inputs); never omit `shouldCreateUser: false` in `signInWithOtp`; always keep `mindflow_recovery_otp_pending` cleared on `verifyOtp` failure and `ResetPasswordPage` mount; never remove `extractAuthHashParams()` or 3-layer link auto-detection fallbacks.
- **Decision ID Registered in Ledger**: `DEC-0037`.
