## 2. Executive Summary
Gen 2 Step 5D (`v1.0.385.4`) redesigns MindFlow's Login & Create Account experience into a calm, distraction-free, zero-tab linear flow built for both first-time/rural smartphone learners and power users. Removed both parallel segmented tab bars (`Sign In | Create Account` and `Password | Email OTP`), replaced the toy-like green-dot email pill with a properly labeled read-only `Email Address` input field (`ReadOnlyEmailField` with leading `Mail` icon and `Change` action), added a focused Sign-In Method Chooser with two vertically stacked 52px action buttons (`Login with Password` and `Login with Email OTP`) plus a clean `Forgot Password?` link, upgraded Create Account into a single clean vertical form accessible via an unmistakable `"New to MindFlow? Create Account"` action, and fixed dual-`<h1>` semantics on desktop (`AuthHeroShowcase.tsx`).

## 4. Engineering Decisions (Path A vs Path B)
### Decision 1: Zero-Tab Linear Auth State Machine, `ReadOnlyEmailField` & Stacked Sign-In Method Chooser (`DEC-0039`)
- **Context & Problem Statement**: Parallel segmented tab switchers (`Sign In | Create Account` and `Password | Email OTP`) confused first-time and rural mobile users, the entered email pill with a green dot looked like a chat presence badge instead of a form input, and toy-like bouncing arrow animations distracted from the authentication flow.
- **Path A (Alternative Considered)**: Keep segmented top tabs and inner `Password | Email OTP` tabs while tweaking colors/spacing.
- **Path B (Path Chosen)**: Eliminate all parallel tab bars across `AuthPage.tsx` in favor of a focused single Sign-In entry (`New to MindFlow? Create Account` CTA at bottom), a dedicated stacked method chooser (`Login with Password`, `Login with Email OTP`, `Forgot Password?`), a proper labeled read-only `Email Address` field (`ReadOnlyEmailField`), a dedicated `signin-recovery` view, and a single vertical `Create Account` form with deterministic hierarchical back (`DEC-0002`).
- **Do-Not-Break Invariant**: Never reintroduce parallel segmented tab switchers (`Sign In | Create Account` or `Password | Email OTP`) or decorative status dots on the entered email field in `AuthPage.tsx`; always display carried-over emails inside `ReadOnlyEmailField` (`Email Address` label + `Mail` icon + `readOnly` input + `Change`), keep `isSendingSignInOtpRef` / `isSubmittingSignUpRef` mutexes and `shouldCreateUser: false` DPDP guard intact, and keep strictly 1 visible `<h1>` on desktop (`AuthHeroShowcase` uses `<h2>`).
- **Decision ID Registered in Ledger**: `DEC-0039`.
