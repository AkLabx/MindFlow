## 2. Executive Summary
Gen 2 Step 5C (`v1.0.385.3`) diagnoses and permanently resolves the `"signal timed out"` failure during Email + Password account creation across both server configuration and client resilience. Live Supabase `auth_logs` revealed that Custom SMTP misconfiguration hung GoTrue's synchronous signup mailer for 10.0s (`504 context deadline exceeded`) plus an upstream gateway retry (`~20.1s` total), causing MindFlow's `15s` client `fetchWithTimeout` to abort mid-flight with a raw browser `DOMException("signal timed out")`. After switching Brevo Custom SMTP to port `587` with valid SMTP credentials (verified live: `POST /signup` `200 OK` in `961ms`, `POST /verify` `200 OK` in `75ms`), this release hardens the client with a `30s` auth-email timeout budget, native `TimeoutError` detection, centralized `authErrorMapper.ts` error normalization + Supabase password-complexity pre-validation, an in-flight signup mutex, and 1-tap `Try Again` + `Continue with Google` timeout recovery UX.

  - Added `>=44x44px` `type="button"` `active:scale-95` inline recovery actions (`Try Again` + `Continue with Google`) on timeout/email-delivery failures, emitting privacy-safe `recovery_action_clicked` telemetry.

  - Added tests for 30s auth-email timeout expansion, native `DOMException('signal timed out', 'TimeoutError')` handling, non-retryable auth email guards, signup timeout recovery UX (`Try Again` + `Continue with Google`), double-submit mutex protection, and upfront password-complexity validation.

## 4. Engineering Decisions (Path A vs Path B)
### Decision 1: Port 587 Custom SMTP Fix + 30s Auth-Email Client Budget, Native `TimeoutError` Guard & Actionable Recovery (`DEC-0038`)
- **Context & Problem Statement**: Email+password signup failed with `"signal timed out"` because a Custom SMTP port/credential hang caused Supabase GoTrue to hit its 10s `context deadline exceeded` (`504`) twice (`~20.1s` with upstream retry), triggering MindFlow's `15s` `fetchWithTimeout` abort; `isOurTimeout` also missed native `DOMException.name === 'TimeoutError'`, and `AuthPage.tsx` dumped raw browser errors with no recovery path.
- **Path A (Alternative Considered)**: Replace Custom SMTP immediately with a custom Supabase `Send Email` Auth Hook Edge Function calling Brevo HTTPS API v3 while keeping a 15s client timeout and raw error rendering.
- **Path B (Path Chosen)**: Resolve the server-side root cause cleanly by switching Brevo Custom SMTP to port `587` with valid SMTP credentials (verified live at `961ms` signup / `75ms` OTP verify, zero extra Edge Function infra) and harden the client across `fetchWithTimeout.ts`, `authErrorMapper.ts`, `AuthPage.tsx`, and `ResetPasswordPage.tsx` (`30s` auth-email timeout, native `TimeoutError` recognition, non-retryable auth email POST guard, upfront password complexity validation, double-submit mutex, and `Try Again` + `Continue with Google` recovery buttons).
- **Do-Not-Break Invariant**: Keep `AUTH_EMAIL_TIMEOUT_MS = 30000` for `/auth/v1/(signup|otp|recover|resend)` in `fetchWithTimeout.ts`, keep `isSafeToRetry()` returning `false` for all auth email-dispatch endpoints, always check `err?.name === 'TimeoutError'` alongside `err?.message`, normalize auth errors via `formatAuthError()` (never leaking raw `"signal timed out"`), and preserve `isSubmittingSignUpRef` double-submit protection.
- **Decision ID Registered in Ledger**: `DEC-0038`.
