## 4. Engineering Decisions (Path A vs Path B)
### Decision 1: Immersive Fullscreen CBT Runner + `Mock_Test_Attempts` `__cbt_meta` Recovery vs `MainLayout`-Wrapped `MockSession`
- **Context & Problem Statement**: Admin-prepared BPSC mock tests (`103`–`150` Qs) require crash-safe reload persistence, 5-state Question Palette navigation, schedule-window enforcement (`DEC-0017`), and native `<dialog>` exit/submit guards without rewriting `useQuizSessionStore` or running a DB schema migration.
- **Path A (Alternative Considered)**:
  - Description: Reuse custom-quiz `MockSession.tsx` (which relies on `useQuizSessionStore`, `window.alert` anti-cheat dialogs, and `MAX_QUIZ_QUESTIONS = 100`) or add dedicated `cbt_meta` columns to `mock_test_attempts`.
  - Why Rejected: `MockSession.tsx` lacked crash-safe active-question/palette persistence, used blocking `alert()` calls, and adding DB columns triggers a DB DDL Circuit Breaker unnecessarily.
- **Path B (Path Chosen)**:
  - Description: Dedicated `PreparedMockExamPage.tsx` inside the `auth-immersive` fullscreen route shell, paired with `100`-UUID chunked ordered hydration and 3-tier IndexedDB + `localStorage` + `mock_test_attempts` (`__cbt_meta` stripped cleanly on submission) crash recovery.
  - Why Chosen / Evidence: Zero DB DDL changes, zero impact on custom student quizzes (`MAX_QUIZ_QUESTIONS = 100` preserved), instant 0ms reload recovery, and verified `0` console errors across `103`-Q Desktop + Mobile execution.
- **Do-Not-Break Invariant**: Always chunk `DB_TABLES.BANK.QUESTIONS` hydration in batches `<= 100` UUIDs with `.is('deleted_at', null)` preserving exact `question_ids` sequence; always strip `__cbt_meta` before marking a `mock_test_attempts` row `completed`; never mount `/exam/:testId` inside `MainLayout` bottom tabs or revive `ExamPlaceholderPage` `"Coming in Phase 4"`/`navigate(-1)`.
- **Decision ID Registered in Ledger**: `DEC-0021` (retiring `OLD-012`)
