## 2. Executive Summary
Delivered operational **Admin Mock Tests CMS Controls** inside `/admin/test-series`—adding URL-synced Category, category-scoped Series, and Status filters with cross-tab `category` preservation, 1-tap readiness-guarded Publish/Unpublish, smart Draft cloning (`status=published` auto-switching to `All`), cascade-safe delete confirmations with exact child counts and downstream hook refresh, and Top-Layer Popover toast migration across all three CMS hooks (`useCategories`, `useSeries`, `useTests`). In parallel, extended `QuestionBuilder` with `subTopic` (424 distinct values) and `examDateShift` (332 distinct values) filtering backed by 7 parallel `get_distinct_values` RPCs (`mindflow_qb_filter_options_v2`) and a new accessible `SearchableFilterCombobox` (`maxVisible=50`) that prevents DOM/accessibility tree timeouts.

## 4. Engineering Decisions (Path A vs Path B)

### Decision 1: URL-Synced CMS Controls, Full-Parity Quick Publish, Smart Draft Clone, Cascade Sync & Popover Hook Migration
- **Context & Problem Statement**: Managing dozens of mock tests in `AdminTestSeriesDashboard` required opening the 4-step studio to duplicate or publish tests, lacked Category/Series/Status filtering, silenced CRUD feedback because CMS hooks still imported unmounted `react-hot-toast`, and left stale client-side child Series/Tests after Postgres `ON DELETE CASCADE` deletes.
- **Path A (Alternative Considered)**:
  - Description: Keep filter state purely in component `useState`, allow quick publish with a minimal `question_ids.length > 0` check, clone all fields verbatim (including dates/published state), keep `react-hot-toast` in `useCategories`/`useSeries`/`useTests`, and rely on page reloads after cascade deletes.
  - Why Rejected: Local-only filters lost context across `series`/`tests` tabs and reloads; partial publish checks risked publishing invalid tests; verbatim cloning leaked `release_date`/`expiry_date`; unmounted `react-hot-toast` failed silently (`DEC-0014`); and unrefreshed child hooks showed deleted rows until hard refresh.
- **Path B (Path Chosen)**:
  - Description: Persist Category/Series/Status in URL search params with cross-tab `category` preservation and post-hydration reconciliation, share full-parity `validateTestForPublish` logic with `AdminTestBuilderPage`, clone tests as Draft (`is_published: false`, nulled `release_date`/`expiry_date`, auto-switching `status=published` $\rightarrow$ `All` with `busyTestIdsRef` lock), show exact child counts in `ConfirmDialog` + refresh `refreshSeries()`/`refreshTests()` after cascade deletes, and migrate all 3 CMS hooks to `useNotification()` Popover toasts.
  - Why Chosen / Evidence: Verified end-to-end on Desktop `1280x800` with persistent URL state, accurate Draft-parent-series & readiness warnings, intact `"SSC CGL · SSC CGL 2025 GK"` relational labels on cloned tests, live Popover toasts, and zero stale child rows after delete checks.
- **Do-Not-Break Invariant**: Never reintroduce `react-hot-toast` in CMS hooks, never bypass `validateTestForPublish` or `TEST_SELECT_QUERY` relational joins on quick publish/clone, and always refresh downstream child hooks after Category/Series cascade deletes.
- **Decision ID Registered in Ledger**: `DEC-0016` (`OLD-008`)

### Decision 2: Capped `SearchableFilterCombobox` (`maxVisible=50`) vs Raw `<select>` / `<datalist>` for High-Cardinality Filters
- **Context & Problem Statement**: Adding `subTopic` (424 distinct values) and `examDateShift` (332 distinct values) to `QuestionFilterBar.tsx` using native `<select>` elements inflated total `<option>` nodes in Step 3 to 923, causing Playwright/WebView accessibility tree extraction to time out (`OP_TIMEOUT` 43–46s) on every mount.
- **Path A (Alternative Considered)**:
  - Description: Render all 424 `subTopic` and 332 `examDateShift` values inside native `<select>` or `<datalist>` elements.
  - Why Rejected: Hundreds of eagerly mounted `<option>` nodes bog down WebView/Playwright HUD accessibility tree serialization and make mobile/desktop scanning slow without search.
- **Path B (Path Chosen)**:
  - Description: Create an accessible `SearchableFilterCombobox` (`maxVisible=50`) whose closed state renders only a single trigger `<button>` (`>=44x44px`, `type="button"`), and whose open state renders an `<input type="search">`, a capped listbox (`maxVisible=50`) with `"Showing 50 of N matches"` truncation guidance, a `44x44px` clear button, and `Escape`/outside-click dismissal.
  - Why Chosen / Evidence: Restored instant Step 3 mount on Desktop `1280x800`, capped visible listbox items at `51` (50 matches + `"All"`), accurately filtered `"Photosynthesis"` (`27` results) and `"01 Oct 2026 (10:00 AM (Shift-1))"` (`25` results), and passed with `0` `button:not([type="button"])`.
- **Do-Not-Break Invariant**: Never render >50 unfiltered options inside raw `<select>` or `<datalist>` tags for high-cardinality `QuestionBuilder` filters (`subTopic`, `examDateShift`); keep `SearchableFilterCombobox` closed-state DOM minimal (`1` trigger `<button>`).
- **Decision ID Registered in Ledger**: `DEC-0016` (`OLD-008`)
