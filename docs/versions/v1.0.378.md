## 2. Executive Summary
v1.0.378 establishes complete 3-tier cache invalidation and preview synchronization between the Admin Question Bank (`AdminQuestionsPage`, `QuestionInspectorDrawer`) and downstream Mock Test preparation pipelines (`AdminTestBuilderPage`, `QuestionBuilder`, `SelectedQuestionsPanel`, and `QuestionPreviewDrawer`). It guarantees that all edits and soft-deletes propagate immediately to downstream caches and distinct filter aggregations without wiping active student CBT attempts, detects and prunes orphaned question IDs in mock tests in 1 tap, and standardizes shared bilingual (English/Hindi) and KaTeX preview formatting.

## 4. Engineering Decisions (Path A vs Path B)
### Decision 1: Question Bank 3-Tier Cache Coordination & Mock Prep Sync
- **Context & Problem Statement**: Editing or soft-deleting questions in admin question management left stale cached payloads across React Query, student runners, and test builder panels. Furthermore, deleting a question that was already included in a mock test could cause silent student test crashes or corrupted scorecards.
- **Path A (Alternative Considered)**:
  - Description: Rely on raw table cache invalidation or complete localStorage wiping (`localStorage.clear()`).
  - Why Rejected: Wiping localStorage would destroy active student in-progress CBT attempts (`mock_active_attempt_*`), while raw table cache invalidation missed memory singletons and IndexedDB metadata entries.
- **Path B (Path Chosen)**:
  - Description: Standardize all question queries on `DB_TABLES.BANK.QUESTIONS`, coordinate cross-feature cache invalidation via `invalidateQuestionBankCaches()` across 3 tiers (React Query, localStorage prefix matching, `MindFlowDB.sync_metadata` prefix cursor deletion, and in-memory singletons) without touching student CBT attempts, and add 100-UUID chunked orphan detection with 1-tap pruning in `AdminTestBuilderPage`.
  - Why Chosen / Evidence: Cleanly eliminates stale payloads, guarantees student safety, keeps test builder synchronized with live question bank state, and validated via 6/6 tests in `adminQuestionsSync.test.tsx`.
- **Do-Not-Break Invariant**: Never purge keys matching `mock_active_attempt_*` or `mock_attempts_*` when invalidating question caches.
- **Decision ID Registered in Ledger**: `DEC-0026`

## 5. Runtime Bugs Caught & Fixes During Development
| Bug / Edge Case Caught | Root Cause | Failure Manifestation | Surgical Remedy Applied |
| :--- | :--- | :--- | :--- |
| Nested Inspector Drawer rendered in View mode instead of Edit mode | `initialEditMode` prop was missing from `QuestionInspectorDrawer` | Clicking "Edit" in `QuestionPreviewDrawer` opened inspector in read-only view mode, requiring a second click to edit | Added `initialEditMode?: boolean` prop and initialized `isEditing: Boolean(initialEditMode)` |
| False-positive orphan pruning during offline or network drops | `validateQuestionIds` treated network fetch failures as missing question IDs | Offline administrators would have all mock test questions flagged as missing | Added `{ throwOnError?: boolean }` to `validateQuestionIds`, checked `navigator.onLine`, and prevented pruning on network errors |
| Question options array type mismatch in preview drawer | Legacy questions store options as `string[]` while modern schema stores `Record<string, string>` | Options rendered as `undefined` or crashed KaTeX rendering | Created `normalizeQuestionOptions` in `QuestionBilingualPreview.tsx` handling `string[]`, stringified JSON, and object dictionaries |
